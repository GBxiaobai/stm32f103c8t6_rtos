## STM32 烧录问题解决
- 环境：Mac Intel + MacPorts OpenOCD 0.12.0 (/opt/local/bin/openocd) + ST-Link/V2 (V2J37S7)
- 问题：Makefile 的 flash 目标用 `adapter driver stlink; transport select swd`，在本机构建 OpenOCD 中不可用
- 原因：该构建中 `stlink` 不是有效驱动名（是 `st-link`，且为 HLA 类驱动，只支持 hla_swd/jtag 传输层）
- 解决：flash 目标改为使用官方 `interface/stlink.cfg`（内部 `adapter driver hla` + `hla_layout stlink`）+ `transport select hla_swd`，并补上未定义的 `OPENOCD ?= openocd`
- 烧写验证通过：device id 0x20036410，flash 64 KiB，verify 无差异
- 注意：hla 模式下 verify_image 前必须先 `reset halt`，否则报 "cortex_m crc algorithm" 错误
- 修改文件：Makefile（flash 目标 + .PHONY）、stlink_test.cfg（去掉 reset_config srst_only，加注释）

## "烧录成功但 LED 不闪"根因定位
- 现象：固件烧入后无现象，用户怀疑没下进去
- 排查：dump_image 导出芯片 flash 与本地 bin `cmp` 逐字节一致 → 下载本身没问题
- 真正根因：link.ld 未放置启动文件的 `.stack`/`.heap` 段 → 孤儿段落到地址 0x0 → `_estack = 0x00000400`（flash 别名区）→ 复位后 SP 错误 → 函数压栈写 flash 无效 → HardFault → Default_Handler 死循环，LED 不闪
- 关键线索：OpenOCD `reset halt` 后 `msp: 0x00000400`（正常应约 0x20005000）；`nm` 看到 `_estack = 0x00000400`
- 修复：link.ld 显式添加 `.stack (NOLOAD) >RAM` 和 `.heap (NOLOAD) >RAM` 段；修复后 `_estack = 0x20000400`
- 排查方法论：①先 dump flash 对比确认下载无误 ②再看 reset halt 后的 PC/MSP ③再看 nm 符号定位异常符号
- 经验教训：自定义启动文件（含 .stack/.heap 段）必须与链接脚本配套，段要么被脚本显式放置，要么用 `_estack = ORIGIN(RAM) + LENGTH(RAM)` 在脚本里直接定义

## 2026-09-17 新增 make erase 擦除目标
- Makefile 新增 `erase` 目标：`stm32f1x mass_erase 0` 全片擦除（64K→0xFF），配置与 flash 目标一致
